# tutorials

**All tutorials go here, and nowhere else.**

- **Who writes here:** developers draft the tutorials the tech lead assigns
  on their checklists, and the lead reviews and finalizes them before the
  client sees them. No other agent writes here.
- **When:** while tutorials are on for a phase (the default), every hands-on
  client task gets one: coding, tool and environment setup, accounts and API
  keys, running commands, manual testing. Approvals and reviews don't. The
  client can turn tutorials off, or back on, at each phase kickoff.
- **One topic per file:** `<topic>.md`, reused across phases where it fits,
  and linked from the client's checklist item.
- **Don't repeat READMEs:** if a README already explains a step (e.g.
  `build/README.md`), link to that section instead.
- **Keep checks simple:** end with a quick check, such as a command to run or
  a page to open, and what the client should see. Never use tests or
  test-driven development to motivate a tutorial.
